Spec 11·08 — KPI Timeline across spaces (prototype)

The one KPI page, tree first. Every KPI you can browse, from every space, in one tree (one parent per KPI). Expand a row (the chart button) to see its timeline: values, targets and the projection. Readings load only for expanded rows. Filter by KPI space (the chosen spaces' KPIs, with their ancestors faded) and by Work from (today's project filter). Add KPI and the row + create in a chosen space. Nothing here talks to Jira.

Questions for review (08 Q1–Q6)
  1. Default view: tree fully expanded, collapsed to the top levels, or the last filter used?
  2. Remember the filter in local storage, or in the URL so a team can bookmark "the Timeline for CHK"?
  3. Current value per row: only for expanded rows, the KPI Reading field's last write (cheap, wrong after a backfill), or a new kpi-latest property?
  4. Next target per row (cheap: it comes from target discovery, not readings)?
  5. No central space: Add KPI has no default without a filter, so the user always picks?
  6. Several rows expanded at once, or one at a time?
